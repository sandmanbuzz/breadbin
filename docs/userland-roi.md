## Ranking logic
Resident sh first (pool pages at every prompt), then the shared lib/err/module leverage, then big untouched basic and tested as/edit; the many 1-page tools are low ROI because a one-page program saves no pool page unless it crosses a boundary.

## Caveats
1. Only the baseline ledger row (433ed4e) was available; no later size rows or per-library/module sizes; branch feat/program-size-ledger is absent, so the table uses the main copy.
2. Test counts are bare-word grep line counts: echo, cat, free, sort, head, clear, date, kill are common words, so those are inflated; "none" for uname is solid, other low counts may hide indirect coverage (e.g. through sh scripts).
3. "Likely win" items marked GUESS come from skimming imports, BSS declarations and name patterns, not from reading every routine or measuring linked bytes; page-boundary effects were not computed.
4. "Untouched" is by commit count to the listed file only; changes via lib.inc, linker config, or kernel exports can alter binaries without touching the file.
5. Nothing was built or run; ROI is a judgment weighting user value, idle footprint, and risk from feature-priority.md and CLAUDE.md, not a measured number.
